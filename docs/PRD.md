## 1. 배경과 목표

### 1.1 문제
정부·지자체 창업 지원사업 공고는 수가 많고 공고마다 대상, 지역, 창업 업력, 연령, 마감일이 다르다. 키워드 검색만으로는 "서울 거주 만 35세 예비창업자가 지금 신청할 수 있는 사업"처럼 조건이 섞인 질문에 답하기 어렵다.

### 1.2 목표
K-Startup 공고를 수집·정제하여 RAG 지식베이스로 구축하고, 자연어 질문과 조건 필터를 함께 사용해 **출처가 붙은 답변**을 제공한다.

### 1.3 프로젝트 목표 (개발자 관점)
- 데이터 수집, 정제, 검색, 생성, 평가, 화면까지 전체 흐름을 직접 구현한다.
- 검색 방식별(dense, hybrid, 필터, 리랭커) 성능을 **수치로 비교**하여 선택 근거를 남긴다.
- 조건(지역, 대상, 마감일)을 실제로 만족하는 결과만 반환하는지 별도로 측정한다.
- 모든 구성은 **비용 없이** 재현 가능해야 한다.

### 1.4 제약 조건
| 구분 | 내용 |
|---|---|
| 비용 | 유료 서비스와 과금 가능성이 있는 서비스를 사용하지 않는다 |
| 작업 시간 | 평일 14:00~17:00, 총 27시간. 주말 작업 없음 |
| 인원 | 1인 |
| 실행 환경 | Mac M3, 메모리 16GB |
| 공개 배포 | 서버 없이 GitHub Pages 정적 사이트만 사용 |
| 데이터 | 공공데이터 이용 조건 준수, 출처 표시. 원본은 저장소에 올리지 않는다 |

## 3. 범위

### 3.1 포함
- K-Startup 공고(30,530건)와 사업 소개(511건) 수집, 최근 기간 공고 색인
- 정제, 정규화, 사업 소개 연결, 품질 리포트
- Hybrid 검색(dense + BM25), 메타데이터 필터, 리랭커
- 질문에서 조건 추출, 화면의 조건 패널과 자연어 질문 병행
- 출처 포함 답변, 근거 없음 거절, FallbackLLM
- 골든셋 평가와 방식 비교
- FastAPI, React 화면, 질문 기록(IndexedDB, 선택)
- 정적 재생 데모(GitHub Pages)

## 8. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 비용 | 유료·과금 가능 서비스를 사용하지 않는다 |
| 보안 | API 키는 `.env`로 관리하고 커밋하지 않는다. 로그에 키, 개인정보를 남기지 않는다 |
| 재현성 | `uv sync`와 문서화된 명령으로 환경을 재현할 수 있다 |
| 데이터 | `data/raw`는 수정하지 않는다. 원본은 저장소에 올리지 않는다 |
| 시점 | 평가와 재생 데모는 기준일(as_of_date)을 고정한다 |
| 신뢰성 | 실행하지 않은 평가의 수치를 문서에 쓰지 않는다 |
| 안내 | 답변은 공고 내용 안내이며 신청 자격을 확정하지 않는다는 문구를 표시한다 |

## 범위 변경 (2026-11-10)

위 표의 "로그인 제외(v1.0, v1.1 로드맵)"은 초기 결정이다. 다음과 같이 범위를 바꿨다.

- 로그인과 사용자별 저장을 **선택 기능**으로 구현했다. 로그인하지 않아도 모든 기능을 쓸 수 있고, 로그인하면 관심 공고와 질문 이력이 계정에 저장되어 다른 기기에서도 볼 수 있다.
- 자체 JWT 대신 Supabase 무료 티어의 이메일 링크 로그인을 화면에서 직접 사용해 구현 비용을 줄였다. 백엔드(FastAPI)는 변경하지 않았다.
- 제외 항목은 그대로다: 회원 관리 화면, 비밀번호 로그인, 서버 측 JWT, 라이브 서버 배포.
- 한계: 무료 기본 메일의 시간당 발송 한도, 무료 프로젝트의 비활성 일시 중지(약 7일). 로그인 없이도 모든 기능이 동작하므로 핵심 시나리오에는 영향이 없다.
- 설계와 검증 기록: `docs/SDD.md` 부록 C, `docs/EVALUATION.md` E-016.
