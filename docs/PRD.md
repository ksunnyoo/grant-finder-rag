## 1. 배경과 목표

### 1.1 문제
정부·지자체 지원사업 공고는 기관별 사이트에 흩어져 있고, 공고마다 대상·지역·마감일·제출서류 형식이 달라 사용자가 자신에게 맞는 사업을 찾기 어렵다. 키워드 검색만으로는 "서울 거주 예비창업자가 이번 달 신청 가능한 사업"처럼 조건이 섞인 질문에 답하기 어렵다.

### 1.2 목표
지원사업 공고를 수집·정제하여 RAG 지식베이스로 구축하고, 조건이 포함된 자연어 질문에 **공고 출처가 붙은 답변**을 제공한다.

### 1.3 프로젝트 목표 (개발자 관점)
- 데이터 수집부터 정제, 검색, 생성, 평가, 배포까지 전체 흐름을 직접 구현한다.
- 검색 기법별(dense, hybrid, rerank, contextual) 성능을 **수치로 비교**하여 선택 근거를 남긴다.
- 모든 구성은 **비용 없이** 재현 가능해야 한다.

### 1.4 제약 조건
| 구분 | 내용 |
|---|---|
| 비용 | 유료 서비스 사용 금지. 로컬 Ollama와 무료 티어만 사용 |
| 기간 | 9 영업일 (주말은 예비일) |
| 인원 | 1인 |
| 실행 환경 | Mac M3, 메모리 16GB |
| 데이터 | 공공데이터 이용 조건을 따른다. 라이선스가 불명확한 원본은 저장소에 올리지 않는다 |

## 2. 사용자와 시나리오

### 2.1 대상 사용자
| 사용자 | 설명 |
|---|---|
| 예비·초기 창업자 | 자신의 지역·업력·대상에 맞는 지원사업을 찾으려는 사람 |
| 포트폴리오 검토자 | 채용 담당자, 개발자. RAG 파이프라인과 평가 방법을 확인하려는 사람 |

### 2.2 대표 시나리오
| # | 질문 예시 | 필요한 기능 |
|---|---|---|
| S1 | "서울 예비창업자가 신청할 수 있는 사업 알려줘" | 메타데이터 필터(지역, 대상) |
| S2 | "이번 달 마감인 창업 지원사업은?" | 마감일 필터 + 질문 재작성 |
| S3 | "초기창업패키지 신청 자격이 뭐야?" | 고유명사 검색(BM25) + 본문 근거 |
| S4 | "해외 진출 지원금 있어?" (자료에 없는 경우) | 근거 없음 거절 |

## 3. 범위

### 3.1 포함 (In Scope)
- 지원사업 공고 150~300건 수집 (API 본문 + PDF 첨부)
- 정제, 정규화, 중복 제거, 메타데이터 구성, 품질 리포트
- Hybrid 검색(dense + BM25), 리랭킹, 메타데이터 필터, 질문 재작성
- 출처 포함 답변 생성, 근거 없음 거절
- 골든셋 기반 평가와 기법별 비교
- API(FastAPI)와 웹 화면(Streamlit), 무료 배포

### 3.2 제외 (Out of Scope)
- 로그인·회원 관리·결제
- HWP 첨부 파싱 (시간이 남으면 추가)
- 사용자별 맞춤 추천 알고리즘, 신청서 자동 작성
- 공고 실시간 자동 갱신 (수집은 수동 CLI 실행)
- 법적·재정적 자문 (답변은 공고 내용 안내이며 신청 자격을 확정하지 않는다)

## 4. 에픽과 스토리

상태 값: 미시작 / 진행 중 / 완료

### E1. 데이터 수집·정제
사용자 가치: 검색 품질의 기반이 되는 깨끗하고 구조화된 공고 데이터를 확보한다.

| ID | 사용자 스토리 | 수락 기준 | 상태 |
|---|---|---|---|
| 1-1 | 개발자는 공고 API에서 공고를 수집하여 원본을 보존할 수 있다 | - 공고 150건 이상이 `data/raw`에 저장된다<br>- 원본 파일은 수정하지 않는다<br>- 수집은 CLI 명령으로만 실행된다 | 미시작 |
| 1-2 | 개발자는 공고 본문과 PDF를 정제하고 메타데이터를 구성할 수 있다 | - 사업명·주관기관·대상·지역·신청 시작일·마감일·지원금액·원문 URL이 구조화된다<br>- 날짜는 ISO 형식, 금액은 원 단위로 통일된다<br>- 전화번호·이메일은 마스킹된다<br>- 중복 공고가 제거된다 | 미시작 |
| 1-3 | 개발자는 정제 전후 품질 리포트를 확인할 수 있다 | - 정제 전후 건수, 필드별 결측률, 중복률이 표로 출력된다<br>- 샘플 20건을 수동 검수한 결과가 기록된다 | 미시작 |

### E2. 색인·검색
사용자 가치: 조건이 섞인 질문에서도 관련 공고를 정확히 찾는다.

| ID | 사용자 스토리 | 수락 기준 | 상태 |
|---|---|---|---|
| 2-1 | 개발자는 공고를 parent-child 구조로 청킹하고 Qdrant에 색인할 수 있다 | - child(검색용)와 parent(답변용) 단위가 구분되어 저장된다<br>- dense(bge-m3)와 sparse(BM25) 벡터가 함께 저장된다<br>- 색인은 CLI에서만 실행되고 서버 시작 시 자동 실행되지 않는다 | 미시작 |
| 2-2 | 사용자는 hybrid 검색과 리랭킹으로 관련 공고를 찾을 수 있다 | - dense와 BM25 결과가 RRF로 결합된다<br>- 상위 20개가 리랭커로 재정렬되어 상위 5개가 반환된다<br>- 고유명사 질문(S3)에서 해당 공고가 상위 5개에 포함된다 | 미시작 |
| 2-3 | 사용자는 질문에 포함된 조건(지역, 대상, 마감월)이 자동 필터로 적용된다 | - 질문에서 조건을 추출하여 메타데이터 필터로 변환한다<br>- 마감된 공고는 기본 검색에서 제외된다<br>- 추출한 조건이 응답에 표시된다 | 미시작 |

### E3. 답변 생성·출처·거절
사용자 가치: 근거가 있는 답변만 받고, 근거가 없으면 없다고 안내받는다.

| ID | 사용자 스토리 | 수락 기준 | 상태 |
|---|---|---|---|
| 3-1 | 사용자는 출처가 붙은 답변을 받을 수 있다 | - 모든 답변에 공고 제목과 원문 URL이 1개 이상 포함된다<br>- 답변은 검색된 본문에 있는 내용만 사용한다 | 미시작 |
| 3-2 | 사용자는 자료에 없는 질문에 "자료에 없음" 안내를 받는다 | - 근거 문서가 없거나 관련도가 기준 미만이면 답변을 생성하지 않는다<br>- 거절 사유와 확인 가능한 공식 링크 안내를 표시한다 | 미시작 |
| 3-3 | 사용자는 웹 화면과 API로 질문할 수 있다 | - `POST /api/ask`가 답변·출처·적용된 필터를 JSON으로 반환한다<br>- Streamlit 화면에서 질문 입력과 출처 확인이 가능하다<br>- 신청 자격은 확정하지 않는다는 안내 문구가 표시된다 | 미시작 |

### E4. 평가·배포
사용자 가치: 구성의 효과를 수치로 확인하고, 누구나 결과를 재현·확인할 수 있다.

| ID | 사용자 스토리 | 수락 기준 | 상태 |
|---|---|---|---|
| 4-1 | 개발자는 골든셋으로 검색·답변 품질을 측정할 수 있다 | - 골든셋 50문항이 작성된다 (단순 조회 20, 조건 필터 15, 다중 문서 5, 근거 없음 10)<br>- Hit@5, MRR, 거절 정확도, 출처 포함률이 스크립트로 계산된다 | 미시작 |
| 4-2 | 개발자는 기법별 성능 비교표를 만들 수 있다 | - dense / +hybrid / +rerank / +contextual 4개 구성이 같은 골든셋으로 평가된다<br>- 결과 표와 해석이 `docs/EVALUATION.md`에 기록된다 | 미시작 |
| 4-3 | 검토자는 공개 URL과 README로 결과를 확인할 수 있다 | - 무료 호스팅에 데모가 배포된다 (불가 시 데모 GIF로 대체)<br>- README에 아키텍처 그림, 실행 방법, 평가 결과, 한계가 있다<br>- 저장소에 키·원본 데이터·개인정보가 없다 | 미시작 |

## 5. 성공 지표 (초안 목표)

기준 성능(dense만) 측정 후 목표를 조정한다. 아래 수치는 목표이며 측정 결과가 아니다.

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| Hit@5 | dense 대비 hybrid+rerank에서 개선 | 골든셋 50문항 |
| 근거 없음 질문 거절률 | 90% 이상 | 근거 없음 10문항 |
| 답변 출처 포함률 | 100% | 전체 답변 |
| 로컬 응답 시간 | 질문당 30초 이내 | 수동 측정 10회 평균 |
| 데이터 품질 | 필수 메타데이터 결측률 10% 이하 | 품질 리포트 |

## 7. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 비용 | 유료 API와 유료 호스팅을 사용하지 않는다 |
| 보안 | API 키는 `.env`로 관리하고 커밋하지 않는다. 로그에 키와 개인정보를 남기지 않는다 |
| 재현성 | `uv sync`와 문서화된 명령으로 환경을 재현할 수 있다 |
| 데이터 | `data/raw`는 수정하지 않는다. 라이선스가 불명확한 원본은 저장소에 올리지 않는다 |
| 신뢰성 | 평가를 실행하지 않은 수치는 README에 쓰지 않는다 |
| 안내 | 답변은 공고 내용 안내이며 신청 자격을 확정하지 않는다는 문구를 표시한다 |
