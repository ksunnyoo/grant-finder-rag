# EVALUATION: 실행 기록

외부 서비스·모델을 실제로 실행한 결과만 일시와 함께 기록한다. 실행하지 않은 항목의 수치는 쓰지 않는다.

## 사전 확인 (2026-11-06)

환경: Mac M3 / 메모리 16GB, Python 3.11, qdrant-client 1.20.0, Ollama(bge-m3, qwen3:8b)

### E-001. Qdrant 로컬 모드의 sparse + RRF + 필터 (PRD Q1)
- 스크립트: `scripts/probe_qdrant.py`
- 방법: `:memory:` 모드, dense(4차원) + sparse 벡터 4건, 지역 필터(서울, 전국) 적용 후 RRF 결합
- 결과: 오류 없이 동작. 필터 조건 밖의 부산 문서는 제외되고 id 1, 4, 2가 순위대로 반환됨
- 한계: 파일 모드(`qdrant_data/`)는 확인하지 않음. 11/10 색인 단계에서 확인 예정
- 결론: Qdrant 로컬 모드를 유지한다 (SDD 4.4절)

### E-002. bge-m3 임베딩 속도 (PRD Q3)
- 스크립트: `scripts/probe_embed_speed.py`
- 방법: 공고 `page_001`의 첫 64건(제목 + 본문 + 신청 대상 내용, 최대 2,000자), 배치 16건, Ollama `/api/embed`
- 결과: 평균 294자, 차원 1024, 총 5.4초, 문서당 0.084초. 1회 측정이며 모델 로딩 시간이 포함됨
- 예상(위 값 기준 단순 환산): 7,369건 약 10.3분, 3,530건 약 4.9분
- 한계: 실제 검색 문서는 사업 소개와 신청 방법이 추가되어 더 길어짐. 11/10 실제 색인에서 재측정 예정
- 결론: 색인 범위는 접수 시작일 2025-01-01 이후 7,369건으로 한다 (SDD 4.3절)

### E-003. 색인 실측 (PRD 2-1, 2026-11-09)
- 명령: `python -m grant_finder_rag.ingestion.index`
- 대상: 접수 시작일(없으면 마감일) 2025-01-01 이후 공고 7,369건 (전체 30,530건)
- 결과: Qdrant 파일 모드에 dense(bge-m3, 1024d) + sparse(BM25) 7,369건 저장, 오류 없음. BM25 단어 사전 13,363개(22초). 임베딩·저장 806초(문서당 약 0.109초)
- 참고: E-002의 예상(약 10.3분)보다 길게 나온 것은 실제 검색 문서가 표본(평균 294자)보다 길기 때문이다 (검색 문서 전체 평균 493자)
- Qdrant 파일 모드에서 sparse 저장이 동작함을 확인 (E-001의 한계 해소)

### E-004. 검색 동작·시간 확인 (PRD 2-2, 2026-11-09)
- 명령: `python -m grant_finder_rag.cli search "서울 예비창업자 지원사업" --mode {dense|hybrid} [--no-rerank]`
- 방법: 질문 1개, 구성별 1회 실행. 필터 미적용. 정확도 평가가 아니라 동작과 시간 확인이다
- 결과: dense 2,753ms(첫 실행), hybrid 1,047ms, hybrid+리랭커는 검색 1,102ms + 리랭크 4,087ms(후보 20건). 세 구성의 1위는 같고 3~5위는 다름
- 관찰: 리랭커 점수가 상위 5건 모두 0.992~0.997. 마감된 공고와 지역이 다른 공고가 섞여 나옴(필터는 2-3)
- 한계: 1회 측정이고 리랭커는 첫 실행의 모델 로딩 시간이 포함될 수 있다. 정확도 비교는 4-2 골든셋 평가에서 한다
- 결론: 리랭커 처리 시간은 질문당 30초 목표 안에 들어간다 (PRD Q4)
